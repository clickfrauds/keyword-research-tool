Guide

How to use this tool — seed formulas, templates & best practices

Get the first step right and everything downstream — scoring, ad groups, SEO clusters, website content — comes out right on its own. Give 3–6 seed keywords, one from each pattern shown on the card. Click Use template to fill the form (niche, location, seeds, deliverable type), then adjust it for your business.

Every run, 5 rules: 3–6 seeds  ·  no brand names  ·  no single generic words (“cleaning” ❌ → “carpet cleaning denver” ✅)  ·  one language per run — pick one of the 23 languages in the dropdown and give seeds in that language (data, ad groups, ad copy, sitelinks and landing pages all come back in it; URLs stay English)  ·  location as free text (“Denver, United States”, or “N/A” for worldwide) — the geo target resolves automatically
The 6 deliverable modes — what each one runs, and what the website builder does with it

Every mode except Locations only ends with a JSON link on the result page. That link is the handoff: paste it into the matching field in the AI Website Builder and the builder stops guessing — it builds from measured search demand instead. The Hands to the builder box on each card tells you exactly which file, which builder mode, and which field.

Existing pages & the two-phase push
GOOGLE ADS · LANDING PAGESthe "Destination not working" fix
The ads never go up before the pages do
Why ads used to be disapproved: the Final URL was your domain plus a slug the run invented, and it was pushed whether or not a page existed there — the page only appeared later, when the website builder used the same JSON. Pausing the campaign does not help: Google reviews the ads either way.
Auto (the default) fetches every Final URL and sitelink before pushing an ad. It refuses more than a 404: a page that returns 200 while its title says "not found", one that redirects to your homepage or another domain, and one too thin to have real content all count as not ready.
If a page is not ready, the campaign, ad groups, keywords, negatives, geo targeting and audiences still go up — none of them carries a URL, so there is nothing for Google to review. Only the ads are held. Deploy the pages, run the same thing again, and the ads go in.
Enabling is separate. The campaign stays Paused unless you pick "Enable the campaign" — turning it on starts spending, and that should never happen as a side effect of a push.
EXISTING PAGESclients whose site is already live
The pages decide the campaign, not the other way round
your URLs → pages read → seeds → Keyword Planner (real volumes) → 1 page = 1 ad group
Set Landing pages to "Already live" and paste the URLs instead of seed keywords. Each page is read for what it actually sells, and that becomes the seeds — then the normal Planner pull runs on them. The strategy still comes from measured volume; the crawl only replaces you typing the seeds in.
One ad group per URL. 5 pages → 5 ad groups. An ad group whose page does not exist stops being possible, and the URLs are used exactly as given, so nothing is ever rebuilt from a slug.
Ad copy matches the page. The run reads each page's real H1 and H2s and writes ads the page can back up — which is what lifts Ad Relevance and Landing Page Experience, and lowers CPC.
Sitelinks that go somewhere. If a page has its own #sections they are used; if not, its sitelinks point at the client's other pages — a better path than scrolling the page the visitor is already on.
Nothing is wasted. Keywords with real volume that no current page sells come back as new_page_opportunities — the client's growth list. Pages too thin to convert come back in page_improvements.json: feed it to the builder and the content improves while the URL stays exactly where it is, so nothing in the campaign has to move.
Area bid tiers — how the Locations CSV decides to bid up or down
GOOGLE ADS · LOCATIONSevery targeted area gets a bid modifier
Bid up where the money is, bid down where the junk clicks are
geo dataset → area names → AI classification → your overrides → Bid Modifier column
What it does: every area in the Locations CSV is graded into one of three tiers — premium (affluent or high-commercial-intent) gets +25%, standard gets no change, and low (labour housing, industrial and warehouse zones, areas with a click-fraud reputation) gets −90%, which effectively switches it off.
What it decides on: the geo dataset supplies only names and Google geo IDs — no income, population or traffic data exists in it. The tiers come from the model's own world knowledge of who lives and works in each named area. That works well in cities it knows well and defaults to standard when it is unsure, which is the safe direction.
Because it is judgment, not data: every non-standard call now ships with a short reason, written into the Locations CSV's Comment column and listed in locations.md. Read that list before you import — the one expensive mistake here is a good area wrongly marked low.
Your knowledge wins: put anything you already know into Premium areas or Low / fraud-prone areas above. Those override the model completely, and they work even with no AI key at all. Use the premium list to protect areas that must never be bid down.
Guardrails: bid adjustments are clamped to Google's −90%…+900% range so one bad value cannot fail the whole campaign push; if most of the map gets marked low the run warns you loudly; and the target country and any area you are targeting can never be added as a negative location.

🚀 Fastest path — API push (no Editor at all)

Fill the API Push — Google Ads customer ID field and the whole campaign goes straight into the account through the Google Ads API — campaign settings, ad groups, keywords with bids, negatives, RSAs, locations with premium/low bid tiers, excluded locations, and audiences. No CSV, no import, no format errors, and it even sets Presence-only location targeting (which a CSV can't).
  1. Validate first (default): Google checks every single operation and reports any problem without creating anything — account stays untouched. Read the API Push Report on the result page.
  2. Validation clean? Run again with Live — the campaign lands Paused (zero spend) in one atomic write: either the whole thing lands or nothing does.
  3. Requirement: the account must be linked to your MCC (Manager Account). Only the guard script stays manual (Ads Scripts can't be pushed via API).
Leave the field blank and you get the CSV files exactly as before — the manual path never goes away.

Full account import order (Ads Editor)

⭐ Shortcut — Master CSV: one file, one import, complete campaign: campaign settings (Search only, Google partners OFF, Manual CPC, Paused) + ad groups + keywords with bids + negatives + RSA ads + locations with premium/low bid tiers + excluded locations + audiences included AND excluded (via the Editor's documented Type column). Import via Account → Import, set the daily budget, review, Post. The ONLY thing left out is the guard script (Tools → Scripts — Ads Scripts can't import from CSV). Steps 1–5 below are the manual per-file path if you prefer it.
  1. Ads Editor CSV — campaigns, ad groups, keywords with suggested bids.
  2. Negatives CSV — the anti-cannibalization layer. Always a separate import — pasting positives and negatives together makes the Editor import everything as positive keywords.
  3. RSA Ads CSV — responsive search ads per ad group.
  4. Audiences CSV (+), then Audiences Negatives CSV (−) — again, two separate imports.
  5. Locations CSV — geo targets per campaign.
  6. Set budgets and bidding manually, review everything, then Post. All campaigns arrive Paused — nothing spends until you enable it.
Golden rule: every file goes through Account → Import (paste text or select file) — never paste into the keyword grids directly; the grids ignore the Criterion Type column.

Google Ads — best practices after the run
  1. Import the CSVs: download Ads Editor CSV (positives) from the result page → Google Ads Editor → Account → Import.   2. Install the guard script: Google Ads → Tools → Scripts → paste the Negative Guard Script → run with DRY_RUN = true for 2–3 days → read the logs → set it to false and schedule hourly. Search terms with conversions are never banned.
  3. Build matching landing pages: copy the Mode 1 landing pages link from the result page → website builder → Mode 1 → paste into Landing pages JSON URL → ONE run generates every ad-group's landing page at the exact slug its RSA Final URLs point to, internally linked, same logo/brand.   4. Account already running? Fill Existing campaign name + Existing ad groups before the run — new groups slot into that campaign with 2-way negative siloing, plus a list of negatives to add to your old groups.
